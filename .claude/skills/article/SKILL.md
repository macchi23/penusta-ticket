記事は private リポジトリ `docs/private/articles/`（penusta-private）に置く。構成・書き方のルール・公開前チェックは `docs/private/articles/article-series.md`、題名・タグ・URL の管理表は `docs/private/articles/README.md`。
書き始める前に両方を読む。手順が 5 つを超えるので Plan Mode で始める。

## 1. 素材集め（researcher）

- 構成メモのその回の行（題材・素材）と、1 つ前の回の本文を渡す。前の回との重複を避け、範囲外（他の回で扱うもの）も伝える
- 「何をしているか → なぜそうしたか → 仕組み（外部仕様の根拠）」を、ユーザーが自分で説明できる形で返させる。ユーザーは実装を任せていて細部を把握していない前提
- **素材の dev-notes とコードを照合させる**。後の機能追加で直った申し送り、古い件数・日付が残っていることが多い（1-2 で 6 件、1-3 で 5 件）。食い違いは一覧で返させる
- 記事に入れる数字（件数、時間、サイズ）は実測させる。開発 DB は SELECT だけ
- 返却: 項目ごとの要点（根拠のパス:行）、骨格案（見出し 6〜8 個）、コード片の候補、図の候補、数字の一覧、範囲外にした方がいいもの

## 2. 方針の提示

- 構成案、範囲外にするもの、dev-notes の食い違いの直し方をユーザーに示す。題名は案を 2 つ、タグは 5 個まで
- 「どう扱うか」の判断（経緯として書くか、コードも直すか、など）はユーザーに聞く

## 3. 下書き（メイン）

- 置き場所は `docs/private/articles/drafts/<回>-<短い名前>.md`。型は既存の回に合わせる（冒頭の HTML コメント、短い「はじめに」で 1-0 へリンク、判断ごとの節、まとめ、シリーズの他の回、末尾の AI 利用の note）
- 自分の言葉で直してほしい箇所は `<!-- TODO: ... -->`。例を 1 つ添える。画像は `![...](TODO)`
- 題名・タグの案は構成メモの「公開前の回の題名とタグ」に置き、構成メモの状態を「下書き」にする
- dev-notes の食い違いは、public 側でメインが直してコミットする（ドキュメント修正）

## 4. 事実確認（researcher）

- 下書きとリポジトリを突き合わせさせる: コード片が実物と一致するか（省略が分かるか）、主張・数字・図が正しいか、推測が推測と書かれているか、言い切りすぎはないか
- 返却は「重大（誤り）/ 中（誤解を招く）/ 軽微」、該当箇所、根拠、置き換える文の案まで
- テストの件数などは verifier の check の結果で確かめる（grep の件数で済ませない）
- 指摘はメインが反映する。数値や向き（A が X、B が Y）は、元のコミットやレビューの記録で裏を取る

## 5. 公開前チェック

- 構成メモの「公開前チェック」（AWS アカウント ID・バケット名・ARN・SSO、業務の話は許可と抽象化）
- `scripts/check.sh secrets`（`docs/private` も検査する）
- Qiita で崩れそうなところ（mermaid の構文、コードブロックのファイル名）は、ユーザーにプレビューで見てもらう
- 下書きと構成メモを private 側でコミット・push する（push 前に `git -C docs/private status`）

## 6. 公開後の後片付け（ユーザーが URL を渡したとき）

- Qiita の API（`https://qiita.com/api/v2/items/<id>`）で題名・タグ・公開日時・本文を取り、手元の下書きと差分を取る。Qiita 側が正なので、違いがあれば手元を合わせる
- private 側: 下書きを `drafts/` から `articles/` へ `git mv`、冒頭コメントの「題名・タグは articles/README.md で管理する」に直す、管理表に行を足す、構成メモの状態を「公開済み」にして「公開前の回の題名とタグ」からその回を消す、前の回のローカル版の「シリーズの他の回」にリンクを足す
- public 側: README の記事一覧に Qiita のリンクを足す
- 両方のリポジトリでコミット・push する
- Qiita 上の前の回の「シリーズの他の回」は Qiita で直接直す必要がある。足す 1 行をユーザーに渡す
- メモリ（`qiita-schedule`）の公開状況を更新する

## 7. 報告と台帳

- 報告: 下書きのパス、自分の言葉で直す TODO の一覧（行番号付き）、事実確認で直した主な点、Qiita に入れる題名とタグ
- サブエージェントの「ハーネスへの気づき」は `docs/harness-backlog.md` に転記する
